1. **建对照表** —— 从 `01-requirement.md` 取出所有验收标准，逐条列出，标明当前有无用例覆盖
2. **盘点已有** —— 先搜现有测试，别重复造
3. **补齐用例** —— 按项目已有测试风格写，用例名或注释里标出对应的 R 编号
4. **真实执行**：

```
{{ commands.test_unit }}
```

> 门禁会**独立重跑一次**这条命令，用退出码判定。报告里写"全部通过"但实际没跑，会在门禁处直接暴露。

失败时的处置：
- 用例写错了 → 修用例重跑
- 代码确实有 bug → 返回 `status: failed`，附失败用例和错误输出，由 leader 打回 developer
- 环境问题 → 写明判定依据（哪条命令、什么报错、为什么判定是环境），返回 `status: blocked`

**不要把失败合理化成"预存在的环境问题"然后放行。** 最多修 3 轮，还不行就返回 blocked。
