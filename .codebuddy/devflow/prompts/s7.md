## 从哪里找经验

重点看这几类信号：

- 门禁**打回过**的地方 → 这类问题容易犯
- 评审里的 🔴 **必修项** → 这类错误容易出
- 测试**未覆盖**的项 → 这类验证容易漏
- 架构师标为高风险但最后没出事 → 风险评估口径可以校准
- 实现时**发现与方案不符** → 探索阶段容易看漏什么

## 必须真正写进经验库

对每条值得留下的经验，执行：

```bash
.codebuddy/devflow/bin/devflow learn \
  --stage <S1..S7> \
  --type <pitfall | best_practice | gate_fail | retry> \
  --detail "<问题模式：什么情况下会出问题>" \
  --fix "<对策：下次该怎么做>" \
  --tags "<逗号分隔>"
```

全部写完后跑一次蒸馏，让系统重算优先级：

```bash
.codebuddy/devflow/bin/devflow distill
```

**写 `--detail` 的要点**：描述**模式**不是**实例**。
- ❌ 实例："token_bucket.cpp 第 78 行没判空指针" —— 下次用不上
- ✅ 模式："限流器的 Allow() 在配置未加载时会拿到空指针，新增限流器实现时都要处理这个时序"

蒸馏会按签名把同类问题聚在一起：反复出现的经验优先级会从 P2 自动升到 P1 再到 P0，之后每次运行都注入到对应阶段的 prompt 里。写得越接近本质，被复用的价值越高。
