回退 devflow 流水线到某个阶段重做。

## 什么时候用

- 实现到一半发现技术方案不可行 → 回退到 S2
- 需求理解错了 → 回退到 S1
- 测试暴露出设计缺陷，不是代码 bug → 回退到 S2

只是代码写错了**不需要回退** —— 让门禁打回 S3 重做就行，回退是给"上游产物本身有问题"用的。

## 执行

```bash
DF=.codebuddy/devflow/bin/devflow
$DF rollback --to S2 --reason "<具体原因>"
```

回退的语义：
- 目标阶段**及其下游**的状态全部清空回 `pending`
- 产物**保留**，标记为 `superseded_by_rollback`（便于对比新旧方案）
- 回退本身会记一条学习事件 —— 频繁回退到同一阶段，说明那个阶段的 prompt 或门禁需要改进

## 回退后

```bash
$DF next
```

拿到目标阶段的 prompt，重新调用对应角色。**在 prompt 里补上回退原因**，否则它很可能产出和上次一样的东西。

## 先确认再执行

回退会丢弃下游已完成的工作。执行前向用户确认：

```
即将回退到 S2 技术方案与任务拆分
原因：<原因>
将清空：S2 S3 S4 的状态（产物保留但标记为已废弃）
已完成的 S3 编码改动不会自动撤销，需要你确认是否手工回滚代码。

确认继续？
```

代码改动不在回退范围内 —— 引擎不会替用户 `git reset`。要不要撤销代码由用户决定。

参数：$ARGUMENTS
