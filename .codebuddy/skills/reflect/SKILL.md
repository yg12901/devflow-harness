# 复盘沉淀

经验只写进 `07-knowledge.md` 等于没写：下次运行不会注入，没人会翻那篇总结。
本 skill 的终点是 `devflow learn` 落进经验库。

## 值不值得记

唯一标准：**下次遇到相似情况，这条会不会改变某人（或某个 Agent）的做法。**

| 算 | 不算 |
|---|---|
| 这个模块有隐式初始化顺序，不按顺序调会静默失败 | 本次改了 3 个文件 |
| 这类需求容易漏掉灰度期间新旧共存 | 构建耗时 2 分钟 |
| 门禁 CHECK-3 反复失败，根因是依赖地图写法没统一 | 测试全部通过 |
| 项目里两个接口看起来等价，实际语义不同 | 评审提了 5 条意见 |

不写：通用软件工程常识、没有模式的一次性笔误、任务流水账。

## 从哪里找

趁上下文还新鲜，重点看：

- 门禁**打回过**的地方
- 评审里的 🔴 必修项
- 测试**未覆盖**却本该覆盖的行为
- 实现时发现和方案不符 —— 说明探索看漏了什么
- 被用户纠正的假设

## 怎么写入

```bash
.codebuddy/devflow/bin/devflow learn \
  --stage S3 \
  --type pitfall \
  --detail "<问题模式：什么情况下会出问题>" \
  --fix "<对策：下次该怎么做>" \
  --tags "cpp,lifecycle,S3"
```

`--type`：`pitfall` / `best_practice` / `gate_fail` / `retry`。

写完跑一次蒸馏，让系统按签名重算优先级：

```bash
.codebuddy/devflow/bin/devflow distill
```

`detail` 写**模式**不是**实例**：

- 差：`token_bucket.cpp:78 没判空指针`
- 好：`限流器的 Allow() 在配置未加载时会拿到空指针，新增实现时都要处理这个时序`

## 不要自己改配方

本 skill **写入经验库**，不擅自新建或改写 `.codebuddy/skills/`、角色定义、门禁配置。
那三样是流程资产，改它们需要人点头。经验库里的条目注入后仍失败，会由引擎降级并标 `needs_rewrite`，再交 S7 重写描述。
